静态博客的安全上线清单

2026-01-20 约 8 分钟 安全

静态站没有数据库和登录后台，攻击面小，但不等于「随便丢上服务器就安全」。下面是我给「杰杰的博客」定的上线基线，部署到云服务器时逐项勾掉即可。

1. 内容安全策略（CSP）

在每个页面的 <meta> 中声明 CSP（本仓库已内置），并在 Nginx 用响应头再下发一份更完整的：

Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self';
  img-src 'self' data:;
  font-src 'self';
  connect-src 'self';
  base-uri 'self';
  form-action 'self';
  frame-ancestors 'none';
  object-src 'none'

原则：无第三方脚本、无 inline script、无 eval。以后若要接入统计或评论，先加白名单域名，并尽量用 integrity + crossorigin。

2. 安全响应头

响应头建议值作用
X-Content-Type-Optionsnosniff禁止 MIME 嗅探
X-Frame-OptionsDENY禁止被嵌套 iframe
Referrer-Policystrict-origin-when-cross-origin控制来源泄露
Permissions-Policycamera=(), microphone=(), geolocation=()关闭不必要能力
Strict-Transport-Securitymax-age=31536000; includeSubDomains强制 HTTPS（上线后开）

3. HTTPS 与证书

  • 用 Let’s Encrypt / acme.sh 申请证书，开启 HTTP→HTTPS 跳转。
  • TLS 只启用 1.2+，优先现代 cipher suite。
  • 证书自动续期，并加入监控（到期前告警）。

4. Nginx 加固点

  • autoindex off; 禁止目录列表。
  • 站点目录权限：运行用户可读，不可写；上传与发布分离。
  • 关闭不需要的模块与默认站点；隐藏版本号 server_tokens off;
  • 限制请求体大小；静态资源可加合理缓存，HTML 用较短缓存。

5. 主机与发布流程

  1. 创建专用系统用户部署站点，不用 root 直接写 webroot。
  2. SSH 仅密钥登录，关闭密码认证；防火墙只放行 80/443 与运维端口。
  3. 发布用 rsync/Git，保留上一版本便于回滚。
  4. 开启访问日志与错误日志轮转；异常 404/扫描行为可事后分析。

6. 站点本身

  • 外链统一 rel="noopener noreferrer"（含 target=_blank 时）。
  • 不引入不可信 HTML 片段；将来若做评论，必须服务端过滤或第三方白名单。
  • 仓库不提交密钥、私钥、服务器 IP 敏感信息。

速查清单

  1. HTTPS + HSTS 已生效
  2. CSP / nosniff / frame / referrer / permissions 已返回
  3. 目录列表关闭，版本号隐藏
  4. 发布用户与 webroot 权限分离
  5. SSH 密钥登录，防火墙最小放行
  6. 日志与备份可恢复

完整配置见仓库 nginx/site.conf 与 SECURITY.md。安全是持续过程，而不是上线当天的一次性勾选。
